# Fusion-интегратор

Плагин для Claude Code для партнёров Fusion AI. Вы продаёте и настраиваете ИИ-агентов клиентам, а плагин учит ваш Claude Code делать это правильно: он знает, что умеет платформа fusion-ai.app и чего не умеет, пишет промпты по методологии Fusion, сам заходит в кабинет клиента, настраивает агента, прогоняет тесты и откатывает неудачные правки.

Версия 0.1.0 (черновик, ещё не опубликован).

## Что внутри

| Что | Для чего |
|---|---|
| Навык `fusion-integrator` | База знаний о Fusion (функции, тарифы, каналы, уведомления, CRM, дожимки, поля заявки, типичные ошибки), правила работы и команды для кабинета клиента |
| Навык `prompt-architect` | Методология написания промптов: бриф, промпт, база знаний, тест-план, регресс. Копия единого источника Fusion |
| Команда `fusion-login` | Безопасный вход в кабинет клиента: пароль вводится скрыто в Терминале, в чат он не попадает |
| Скрипты `fusion.py` | Список агентов, создание, заливка промпта с побайтной сверкой, база знаний, поля заявки, дожимки, уведомления, тест-чат, бэкап и откат |

## Что нужно

- Claude Code (приложение Claude Desktop, вкладка **Code**, или команда `claude`).
- Python 3.9 или новее (на Mac он обычно есть: проверка `python3 --version`).
- Для каждого клиента: почта и пароль от его кабинета на fusion-ai.app. Если кабинет создан через вход Google (пароля нет), попросите клиента задать пароль в настройках.

## Установка

Вставьте в чат Claude Code одну фразу (адрес маркетплейса вам даст команда Fusion после публикации):

```
Установи плагин Fusion-интегратор: запусти claude plugin marketplace add <адрес от Fusion>, потом claude plugin install fusion-integrator@fusion-integrator и скажи, когда закончишь.
```

Если Claude отвечает «Operation not permitted» или «Read-only file system», это не поломка: Claude Desktop запускает команды в песочнице. Поставьте кнопками: **«+»** у поля ввода → **Add plugins** (или **Plugins** → **Browse plugins**), добавьте маркетплейс, выберите `fusion-integrator`. Или вставьте в поле ввода по очереди, каждую отдельным сообщением:

```
/plugin marketplace add <адрес от Fusion>
/plugin install fusion-integrator@fusion-integrator
```

Потом закройте сессию и откройте заново (или `/reload-plugins`) и напишите: «Подготовь вход в кабинеты клиентов» — Claude поставит команду `fusion-login` (один раз).

Обновление плагина: `/plugin marketplace update fusion-integrator`, затем `/reload-plugins`, и снова «Подготовь вход в кабинеты клиентов».

## Первый вход в кабинет клиента

Пароль клиента **никогда не пишется в чат с Claude**. Вход делается так:

1. Скажите Claude: «Зайди в кабинет клиента, назови его `salon-nur`».
2. Claude попросит открыть **обычное окно Терминала** (не чат) и выполнить:
   ```
   fusion-login salon-nur
   ```
3. Терминал спросит почту и пароль клиента. Пароль вводится скрыто: символы не появляются, это нормально. Нажмите Enter.
4. Терминал напишет «Готово: вход выполнен». Вернитесь в Claude и напишите «готово».

Что произошло: скрипт вошёл на fusion-ai.app, сохранил **только токен сессии** (временный ключ, не пароль) в `~/.config/fusion-integrator/salon-nur.json` с правами «только вы» и сразу забыл пароль. Ни пароль, ни токен не печатаются на экране и не попадают в чат. Закончили работу — `fusion-login salon-nur --logout` удалит сессию. Если сессия истекла, Claude попросит повторить вход.

Если Claude сам попробует запустить `fusion-login` из чата, скрипт откажется: он работает только в настоящем окне Терминала. Это защита. Важно: запускайте вход в **отдельном** окне Терминала, а не в том, где идёт сессия Claude Code.

## Пример: «собери агента для салона по этим материалам»

Положите в папку материалы клиента (прайс, описание услуг, ссылки на Instagram и сайт, пара переписок менеджера) и скажите Claude:

> Собери агента для салона красоты «Нур» по материалам из этой папки. Клиент в сессии `salon-nur`.

Что будет дальше:

1. Claude изучит материалы и задаст 1–3 вопроса за раз: кто клиенты салона, что должен сделать агент (заявка на консультацию), какие данные нужны мастеру, нужны ли напоминания молчащим.
2. Напишет промпт по методологии, проверит его линтером и покажет вам итог (знаки, что включено, что нет).
3. Создаст агента (без каналов, клиентам он пока не отвечает), загрузит базу знаний (услуги, цены), задаст поля заявки (телефон обязателен).
4. Попросит клиента создать группу Telegram для заявок и добавить туда `@FusionNotify_Bot`, затем вы вдвоём подтвердите код от бота.
5. Спросит вашего «да» на тест-чат и скажет, сколько сообщений он спишет у клиента. Прогонит набор сценариев и покажет диалоги.
6. Исправит замеченное и прогонит заново весь набор. Перед выкаткой попросит ваше «ок», вы подключите канал (WhatsApp, Instagram) в кабинете клиента, и Claude включит агента.

Перед каждой правкой Claude делает бэкап. Если что-то пошло не так, скажите «откати» — вернутся промпт, настройки, дожимки и поля заявки.

## Советы по безопасности

- Токен сессии лежит в `~/.config/fusion-integrator/` с правами «только вы», но Claude работает от вашего имени и технически мог бы его прочитать. Правила плагина запрещают это, а надёжнее добавить запрет в настройки Claude Code (`permissions.deny` для `Read(~/.config/fusion-integrator/**)`) и включить песочницу.
- Бэкапы с промптами клиентов лежат там же (`backups/`). Закончили работу с клиентом: `fusion-login <имя> --logout` и удалите папку `backups/<имя>` при необходимости. Токен на сервере действует до своего срока, если подозреваете утечку, смените пароль клиента в кабинете.
- Включение агента (`agents active on --confirm-live`) и тест-чат (`chat --confirm-spend`) добавьте в список «спрашивать» в разрешениях Claude Code, чтобы они не выполнялись без вашего «да».
- Тест-чат ограничен 100 сообщениями в сутки на клиента.

## Правила, которые плагин соблюдает

- Всё делается в кабинете клиента, чужие кабинеты не трогаются.
- Бэкап перед правкой, регресс перед выкаткой.
- Не обещаются функции, которых нет в платформе. Запись на «свободное время» не обещается: агент не видит окошек.
- Уведомления о заявках только через `@FusionNotify_Bot`, отдельный бот клиенту не нужен.
- Без поля «Телефон» в заявке агент не передаст заявку менеджеру, поэтому оно ставится всегда.
- Деньги, тарифы и скидки решает только команда Fusion.

## Для тех, кто обновляет плагин (команда Fusion)

- Методология копируется из единого источника скриптом: `python3 tools/sync-methodology.py` (проверка свежести: `--check`). Папка источника по умолчанию — рабочая папка `prompt-architect/`, другой путь задаётся переменной `FUSION_PROMPT_ARCHITECT_SRC`. Скрипт убирает из копии названия клиентов и сам ищет утечки перед записью.
- Локальный файл `tools/leak-names.local.txt` (список слов-табу) в git не попадает.
- Тесты без сети: `python3 -m unittest discover -s tests`.
- Структура: `plugins/fusion-integrator/skills/fusion-integrator/` (SKILL.md, references/, scripts/), `plugins/fusion-integrator/skills/prompt-architect/` (SKILL.md, references/).
- Публикация (GitHub, маркетплейс) только после проверки безопасности и отдельного «да».

## Что плагин НЕ делает

Не подключает каналы за вас (QR WhatsApp, вход Meta), не включает CRM-интеграции, не меняет тарифы и оплату, не рассылает сообщения, не читает переписки клиентов.
