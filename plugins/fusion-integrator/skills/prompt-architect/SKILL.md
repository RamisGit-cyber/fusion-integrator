# Prompt Architect (методология Fusion)

Единый источник методологии лежит рядом, в файлах:

- `references/architect-core.md` — ядро: как думать, архитектура промпта, платформа и инструменты, процесс (ШАГ 0–11), анти-паттерны, формат вывода. **Прочитай целиком до первого слова промпта.**
- `references/lessons-checklist.md` — 42 урока с проверкой. **Прочитай целиком.**
- `references/SOURCE.json` — откуда копия и контрольные суммы.

Эти файлы — механическая копия, а не пересказ. Руками их не правят: обновление делает `python3 tools/sync-methodology.py` в проекте плагина (при необходимости партнёру достаточно обновить плагин). Если в ядре встретишь ссылку на файл, которого здесь нет (например полный архив уроков), он не входит в плагин: действуй по тому, что есть.

## Как применять вместе с навыком fusion-integrator

1. Бриф и сборка идут по ШАГАМ 0–11 ядра. Задавай 1–3 вопроса за раз, между шагами резюме, без терминов («агент сам отправит фото», а не «тулза»).
2. Обязательные шаги, даже при спешке: 2b (политика лида), 2c (поля заявки), 3 (действия: файлы, запись, CRM, передача человеку, сбор данных, дожимки, человек параллельно).
3. Проверка перед заливкой: линтер методологии (шаг 11А) + `prompt lint` из навыка `fusion-integrator`. Сценарии для тест-чата — формат в `fusion-integrator/references/primery/scenarios.json`.
4. Заливка и тесты — командами навыка `fusion-integrator` (`prompt push`, `chat`). Регресс — полный набор, не один кейс.
5. Правка существующего промпта — раздел `<правка_существующего_промпта>` ядра: источник поведения → замена, а не добавка.

## Правила Fusion, которые сильнее вкуса

- Тон агента тёплый: 1–2 уместных смайлика, «Вы» сохраняется. Сухой тон — брак.
- В примерах нет записи на «свободное время» (агент не видит окошек): заказ, консультация, передача менеджеру.
- Идентичность по умолчанию: честный ИИ-помощник с именем. Запрет «не говори, что ты ИИ» не пиши.
- Запрещённые имена персон отслеживает линтер (`prompt lint`): если он ругается на имя, возьми другое.
- Названия моделей и инструментов, которых нет в списке ядра, в промпт не пишем.
- Служебные пометки и шапки в файлах базы знаний не допускаются.
- Не копируй примеры из других ниш: уникальность проверяй вопросом «если сменить нишу, промпт всё ещё подходит?»; если да — переделай.
