# Порядок работы: от брифа до выкатки

## 0. Подготовка
- Имя клиента для сессии, вход через `fusion-login`, `agents list` (понять, что уже есть), `account` (подписка и сообщения).
- Для нового клиента делай нового агента, а не переделывай существующего. Для правки живого сначала `agents clone`, правь копию.
- Материалы клиента: сайт, Instagram, прайс, переписки менеджеров, договор-оферта. Прочитай всё до вопросов. Не задавай клиенту технических вопросов про платформу: решай сам или спрашивай команду Fusion.

## 1. Бриф (1–3 вопроса за раз)
По методологии `prompt-architect` (ШАГ 1–9). Минимум:
1. Чем занимаются, кто покупатель, средний чек, цикл сделки.
2. Идеальный итог диалога (заявка, заказ, консультация, визит).
3. Какие данные нужны менеджеру минимум (телефон обязательно).
4. Файлы: прайс, каталог, фото? Будут загружены?
5. CRM: ведёте? Куда класть заявки?
6. Когда диалог уходит человеку, кто этот человек, график.
7. Дожимки: нужны ли, сколько шагов.
8. Языки (русский, кыргызский, другие), тон, реальные переписки менеджеров.
9. Чего агент НЕ делает и не знает.
10. Запись на время: только заявка (по умолчанию). Календарь только по подтверждению Fusion.
Идентичность агента: честный ИИ-помощник с именем («Лейла, виртуальный помощник») или человеческая персона. Для старта рекомендуй честного помощника: клиенты спокойнее реагируют на ошибки.

## 2. Сборка
1. Промпт (XML-блоки, без Markdown) → `prompt lint`.
2. `agents create --name "…" --prompt-file …` (агент создаётся без каналов).
3. Факты в базу: `kb upload`. Файлы без служебных шапок. Дат и дней недели нет.
4. `fields set` (Телефон обязателен), при нужде свои поля.
5. Дожимки: `followups set`.
6. `agents set --temperature 0.2 --voice on --image on` (если нужны голос и фото).
7. Уведомления: `notify link`, группа, код, `notify confirm`.

## 3. Тесты
Файл сценариев (формат `primery/scenarios.json` — простой, для тест-чата) и расширенный `scenarios.json` методологии (id, turns, must, must_not) для проверки глазами. Минимум 25 кейсов по классам из методологии: приветствие на первых сообщениях, цена и факт, неизвестное, лид по политике, дословные тексты, файл, эскалация, «вы бот?», грубость, посторонняя тема, языки, дожимки.

Правила прогона:
- Перед запуском скажи человеку: «Прогон отправит N сообщений, они спишутся с тарифа клиента, осталось M. Запускаю?» Только после «да» добавляй `--confirm-spend`.
- Один диалог за раз, ссылка тест-чата живёт ограниченное время; плагин сам удаляет её в конце.
- Проверяй ответ глазами человека: тон, длина, смайлики, выдумки, цены, обещания записи, служебные хвосты.
- Нашёл брак — правь источник (пример → противоречащее правило → документ базы → поля заявки → платформа), потом заново весь набор, а не один кейс.

## 4. Регресс перед выкаткой
«Готово» можно говорить, когда:
- прогнан весь набор, нет критичных падений (выдуманная цена или факт, потеря заявки, утечка вызова инструмента, неверный язык);
- заявка реально пришла в группу один раз;
- `prompt push` сверил промпт побайтно, бэкап «до» лежит (`backups`);
- человек сказал «ок».

## 5. Выкатка
1. Каналы подключает человек (QR, вход Meta), ты проверяешь `channels`.
2. `account`: подписка активна, сообщений хватает.
3. `agents active on` — только после «ок».
4. Живая проверка с телефона человека: приветствие, цена, заявка в группе.
5. Короткое сообщение клиенту: что готово и как менять тексты. Без слов «ошибка на нашей стороне»; про сбои — «посмотрим и поправим».

## 6. Правка работающего агента
Бэкап (автоматически) → правка на копии → весь регресс → заливка в боевого → побайтная сверка → при провале `restore`. Новая фича, а не правка — согласуй с партнёром.

## 7. Откат
`backups --agent ID` — список; `restore --agent ID` — из последнего, `--file` — из выбранного. Откат возвращает промпт, настройки агента, дожимки и поля заявки. Файлы базы знаний автоматически не возвращаются (в бэкапе только список имён): загрузи нужный файл заново.
